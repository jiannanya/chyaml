# chyaml

`chyaml` is a minimal C++20 YAML-subset parser and writer designed for embedded and resource-constrained applications. The entire library consists of a single header, `chyaml.hpp`, with no third-party dependencies and nothing to compile or link separately.

Design goals:

- Fast: a single linear parse pass with no string copies during borrowed parsing;
- Memory-efficient: each parsed node occupies exactly 20 bytes, while strings remain as views into the input;
- Small: a compact single-header API, with unused writer templates never instantiated;
- Predictable: the default maximum nesting depth is 32 and can be configured at compile time;
- MCU-friendly: the writer can target a fixed buffer without any heap allocation.

## Supported YAML Subset

Supported features:

- Space-indented block mappings;
- Block sequences, including scalar and object sequences;
- Compact object entries using `- key: value`;
- Single-quoted and double-quoted scalars, plus common double-quote escapes;
- Full-line and end-of-line comments;
- Reading `null`, booleans, integers, floating-point values, and strings;
- Skipping `---`, `...`, and `%...` lines.

Intentionally unsupported features:

- Anchors, aliases, tags, and complex keys;
- `|` and `>` multiline scalars;
- Structural parsing of flow collections; `[a, b]` and `{a: b}` are retained as plain scalars;
- Multi-document semantics, implicit typing, and full YAML specification compatibility;
- Tab indentation or mixing mapping and sequence entries in the same container.

Input should be generated by this library's writer or follow the simple format above. Indentation width may vary, but sibling nodes must align. Two spaces are recommended throughout.

## Include

```cpp
#include "chyaml.hpp"
```

Enable C++20 when compiling:

```sh
g++ -std=c++20 app.cpp
clang++ -std=c++20 app.cpp
```

Use `/std:c++20` with MSVC.

## Quick Read Example

```cpp
#include "chyaml.hpp"
#include <string_view>

int main() {
    constexpr std::string_view text = R"(
device:
  name: "pump-a"
  rate: 120
  enabled: true
  pins:
    - 3
    - 5
)";

    chyaml::document doc;
    if (!doc.parse(text)) {
        const auto e = doc.error();
        // chyaml::message(e.code), e.line, e.column
        return 1;
    }

    const auto device = doc.root()["device"];
    const auto name = device["name"].value_or<std::string_view>({});
    const int rate = device["rate"].value_or(0);
    const bool enabled = device["enabled"].value_or(false);

    const auto pins = device["pins"];
    for (std::size_t i = 0; i < pins.size(); ++i) {
        const int pin = pins[i].value_or(-1);
        (void)pin;
    }
    (void)name;
    (void)rate;
    (void)enabled;
}
```

`operator[]("key")` finds an immediate mapping child, while `operator[](index)` returns an immediate child by position. A failed lookup returns an invalid node that can be tested in a condition.

```cpp
if (auto port = doc.root()["network"]["port"]) {
    int value = 0;
    if (port.read(value)) {
        // Use value.
    }
}
```

### Input Lifetime

`parse()` is the fastest and most memory-efficient borrowed mode. String views stored by nodes point into the supplied text, so that text must remain alive and at a stable address for as long as the `document` and its nodes are in use.

```cpp
std::string yaml = load_file();
chyaml::document doc;
doc.parse(yaml);            // doc borrows yaml
```

Use `parse_copy()` when the document needs to own its input:

```cpp
chyaml::document doc;
doc.parse_copy(load_file());
```

Neither mode modifies its input. Use `doc.owns_source()` to distinguish the modes, and call `shrink_to_fit()` after parsing to release spare capacity where possible.

### Node Types and Strings

```cpp
auto n = doc.root()["items"];

n.type();        // chyaml::kind
n.is_mapping();
n.is_sequence();
n.is_scalar();
n.is_null();
n.key();         // std::string_view
n.scalar();      // outer quotes removed; escapes are not decoded
```

Reading into `std::string_view` does not allocate and does not decode escape sequences. Reading into `std::string` decodes the common escapes emitted by the writer:

```cpp
std::string decoded;
if (doc.root()["message"].read(decoded)) {
    // decoded may contain newlines, tabs, and other escaped characters
}
```

Numeric conversion uses `std::from_chars`, does not modify the global locale, and does not allocate memory. A conversion succeeds only when it consumes the complete scalar.

## Writing to a String

String arguments are always emitted as double-quoted strings. Numeric and boolean overloads are emitted as scalars. Use `raw()` when you need to supply an unquoted scalar yourself.

```cpp
chyaml::writer out;

out.begin_mapping();
out.value("name", "pump-a");
out.value("rate", 120);
out.value("enabled", true);

out.begin_sequence("pins");
out.value(3);
out.value(5);
out.end();

out.begin_sequence("peers");
out.begin_mapping();
out.value("host", "10.0.0.2");
out.value("port", 9000);
out.end();
out.end();

out.end();

if (!out.complete()) return 1;
const std::string_view yaml = out.view();
```

Output:

```yaml
name: "pump-a"
rate: 120
enabled: true
pins:
  - 3
  - 5
peers:
  -
    host: "10.0.0.2"
    port: 9000
```

Every `begin_mapping()` or `begin_sequence()` must have a matching `end()`. The root container must also be started and ended explicitly. An invalid call order or output failure changes `ok()` to `false`.

## Heap-Free Writing

`buffer_sink` writes into caller-provided memory and does not append a `\0` terminator. If the buffer is too small, the current and all subsequent operations return `false`.

```cpp
char storage[256];
using fixed_writer = chyaml::basic_writer<chyaml::buffer_sink, 8>;
fixed_writer out{chyaml::buffer_sink(storage, sizeof storage)};

out.begin_mapping();
out.value("id", 7);
out.value("state", "ready");
out.end();

if (out.complete()) {
    std::string_view yaml = out.view();
    // Send yaml.data(), yaml.size().
}
```

The template argument `8` is the maximum container depth for this writer instance. A smaller value further reduces the writer object's size.

## Object Sequences

Each object-sequence entry is an unkeyed mapping container:

```cpp
out.begin_sequence("sensors");

out.begin_mapping();
out.value("id", 1);
out.value("unit", "C");
out.end();

out.begin_mapping();
out.value("id", 2);
out.value("unit", "%");
out.end();

out.end();
```

When reading, each immediate sequence child represents one entry:

```cpp
auto sensors = doc.root()["sensors"];
for (std::size_t i = 0; i < sensors.size(); ++i) {
    auto item = sensors[i];
    int id = item["id"].value_or(-1);
    (void)id;
}
```

## Resource and Performance Notes

- Parsing complexity is `O(input bytes)` and parsing is non-recursive;
- Every node is a compact 20-byte record, while keys and values remain in the original input;
- `document` stores a single node vector; borrowed mode keeps no input copy;
- Key and index access perform a linear scan within the current container and do not build a hash table;
- The parser's depth stack lives on the call stack and supports up to 32 levels by default;
- Numeric output uses `std::to_chars` without iostream or locale facilities;
- Fixed-buffer writing performs no dynamic memory allocation.

Small configuration files generally benefit most from the compact representation and zero setup overhead. If a large mapping is queried repeatedly, cache the required nodes in application code instead of repeatedly searching from the root.

## Compile-Time Configuration

Define the maximum parser and default writer depth before including the header:

```cpp
#define CHYAML_MAX_DEPTH 16
#include "chyaml.hpp"
```

The value must be greater than zero. Lowering it reduces the parser's temporary stack and the default writer object's size. Input exceeding the limit reports `chyaml::error_code::depth_limit`.

## Error Handling

```cpp
chyaml::document doc;
if (!doc.parse(text)) {
    const chyaml::parse_error e = doc.error();
    std::string_view reason = chyaml::message(e.code);
    // e.line and e.column are 1-based; global size errors may report 0
}
```

After a parse failure, nodes created before the error may remain in the document. They are useful only for diagnostics and must not be treated as a complete configuration. Call `parse()`, `parse_copy()`, or `clear()` to reuse the object.

## Recommendations

- Prefer `parse()` for trusted configurations;
- Call `reserve()` first when the approximate node count is known to avoid vector growth;
- Prefer the library writer at the configuration producer to keep output inside the supported subset;
- For untrusted input, validate field ranges, required values, and sequence lengths in application code.
